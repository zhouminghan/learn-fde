# P9.1 Theme Audit

Audit date: 2026-11-11

Audit basis:

- `docs/.vitepress/theme/styles/custom.css`
- `docs/.vitepress/theme/Layout.vue`
- `docs/.vitepress/theme/index.ts`
- All page, lesson, visual, and demo components under `docs/.vitepress/theme/components/`
- Existing E2E and unit tests
- Calculated WCAG contrast from the declared sRGB colors

The audit was performed by the Orchestrator and three independent read-only audit agents. The audit agents did not edit files or run builds.

## Summary

The existing theme already has paired Light and Dark values and a pre-hydration boot script, but color roles are conflated and several states are not safe:

- `brand-1` is used as both text and a solid action background.
- Dark links and active labels can fall below 1.5:1.
- Filled buttons use fixed white text over light dark-mode accents.
- Light muted text and several small status badges fall below 4.5:1.
- Mermaid and SVG diagrams use hard-coded palettes or color-only status.
- Theme persistence reads localStorage at boot but does not reconcile IndexedDB or react to cross-tab changes.
- Existing tests do not cover contrast, axe, full Light/Dark visual regression, or persistence edge cases.

## Findings

| Priority | Location | Current behavior | Impact | Required change |
| --- | --- | --- | --- | --- |
| P0 | `custom.css`, QuestionView, navigation | Dark `--vp-c-brand-1` maps to `#1c3853` on `#151c24`/`#202a34`, about 1.4:1/1.2:1. | Links, active navigation, selected options, tags, and bookmarks are nearly invisible. | Separate text-safe brand tokens from solid-fill tokens; map VitePress brand roles correctly. |
| P1 | Home, LessonControls, Practice, Exam | Primary hover uses a light dark-mode navy with white text, about 1.6:1. Light hover is indistinguishable from base. | CTA feedback becomes unreadable or disappears. | Add explicit brand fill, hover fill, and on-brand foreground tokens. |
| P1 | Home, Lab, Exam, Records | Fixed `#fff` on dark accent, teal, and danger fills ranges from 1.95:1 to 2.58:1. | Approval, submit, and destructive actions fail AA. | Add on-accent, on-teal, and on-danger paired tokens. |
| P1 | Course, QuestionView, Records | Light status text on soft backgrounds: accent 2.76:1, teal 3.30:1, warning 3.62:1, danger 4.11:1, success 4.15:1. | Small badges and mastery labels are hard to read. | Define status-on-soft foregrounds at 4.5:1 or better. |
| P1 | Global muted text | Light `--lf-text-3` is 3.2:1 to 3.7:1 on page and elevated surfaces. | Metadata, IDs, source labels, and captions fail AA. | Darken the light tertiary text token and use it only where contrast is verified. |
| P1 | Exam answer sheet | Answered and marked classes overwrite the same background; marked state hides whether a question was answered. | Users can miss unanswered questions before submission. | Compose answered and marked states; add a non-color marker and complete accessible name. |
| P1 | Mermaid and fenced diagrams | Explicit light theme variables override dark output; custom diagram nodes use hard-coded palettes. | Diagrams retain light nodes or lose connector contrast after theme changes. | Use CSS-token-derived Light/Dark Mermaid profiles and rerender on theme change. |
| P1 | ArchitectureDiagram | Dark core fill/stroke nearly match the diagram background; clickable SVG groups are not keyboard accessible. | Nodes can disappear and keyboard users cannot open details. | Add node tokens, focus semantics, keyboard activation, and color-independent kind labels. |
| P1 | DiagramFrame | Fullscreen mode has no dialog semantics, focus entry/restore, or background isolation. | Focus can escape behind the overlay. | Add modal semantics, focus management, Escape handling, and background isolation. |
| P1 | InteractiveWorkflow | Timeline items are click-only `<li>` elements and status is color-only. | Keyboard and color-vision users cannot operate or interpret the timeline. | Add focusable controls, keyboard activation, `aria-current`, visible status labels, and a live region. |
| P2 | LessonControls | Storage warning references undefined `--vp-c-red`. | Warning loses semantic styling. | Use the danger token. |
| P2 | Global VitePress mapping | `--vp-c-default-2/3` remain light in dark mode; VitePress brand, button, code, and custom-block mappings are incomplete. | Built-in controls and blocks can drift from the design system. | Define complete Light/Dark VitePress role mappings. |
| P2 | Focus | Focus uses accent color that can be below 3:1 on soft backgrounds. | Keyboard focus can be hard to see. | Add a stronger focus ring token and a consistent focus-visible recipe. |
| P2 | Records | Mobile exam rows keep three fixed columns. | Dates and statuses wrap excessively at narrow widths. | Use a responsive two-row layout below 640px. |
| P2 | Lab | Selected node has no visual selection state. | Detail-panel context is unclear after pointer or touch selection. | Add a semantic selected state. |
| P2 | Theme persistence | localStorage boot state is not reconciled with IndexedDB; cross-tab updates are ignored; blocked localStorage can abort setup. | Restored preferences can be ignored and tabs can diverge. | Introduce a guarded shared preference contract and sync path. |
| P2 | Theme boot | Boot script duplicates component logic and does not set `color-scheme` or browser `theme-color`. | Browser chrome and control state can temporarily disagree with the page. | Share boot values, set color scheme, and update meta theme color. |
| P2 | Mermaid loading | Diagram host has no reserved height or loading state. | Async render causes blank-frame layout shift. | Add accessible loading state and reserved minimum height. |
