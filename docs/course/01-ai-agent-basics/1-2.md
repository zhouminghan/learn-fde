# 大语言模型的进化之路：从“会接龙”到“会做事”

## 本章目标

学完本章后，你应当能够：

- 解释 Token、预训练、推理与上下文窗口的含义。
- 说明大语言模型如何从“预测下一个词”发展到能够调用工具完成任务。
- 识别模型的能力边界与常见失败模式。

## 核心概念

- **Token**：模型处理文本的最小单元，可能是字、子词或词。
- **预训练**：在通用语料上学习语言与知识表征的阶段。
- **推理**：模型根据输入生成输出的过程。
- **上下文窗口**：模型一次可接收的最大 Token 数量。
- **工具调用**：模型按约定格式请求执行外部函数的能力。

## 原理与机制

大语言模型的核心任务可以理解为“给定上文，预测下一个 Token”。当这一能力扩展到足够大规模时，模型表现出推理、归纳、指令遵循等涌现能力。要让模型“会做事”，还需要在推理阶段提供上下文、示例与工具描述，并让模型输出结构化的调用请求。

```mermaid
flowchart LR
  A[海量语料] --> B[预训练]
  B --> C[基础模型]
  C --> D[指令微调]
  D --> E[可对话模型]
  E --> F[工具调用]
  F --> G[完成真实任务]
```

## ADP 对应能力

在 ADP 中，模型配置决定应用使用哪类基础模型；角色指令负责约束行为；工具与连接器让模型具备执行外部操作的能力。理解 Token 与上下文窗口，有助于设计提示词和知识库切分策略。

## 企业场景

一个工单助手需要查询 CRM 并创建工单。模型先理解用户意图，再调用查询接口，最后按接口返回结果生成答复。如果上下文窗口有限，就需要通过检索只把相关记录放入上下文，而不是把整个数据库塞进去。

## 风险与常见误区

- **误区**：模型“知道”所有事实。模型是基于统计的生成器，可能产生幻觉。
- **误区**：上下文越长越好。过长上下文会增加成本、延迟与噪声。
- **风险**：没有验证就信任工具调用结果。

## 验收标准

能够解释 Token 与上下文窗口，并说明模型通过工具调用完成任务的机制。

## 本章小结

大语言模型从预测下一个 Token 出发，通过预训练、指令微调与工具调用，逐步具备完成真实任务的能力。上下文管理与结果验证是工程化的关键。

## 自测题

1. Token 是什么？  
   **答**：模型处理文本的最小单元，由分词器把文本切分为字、子词或词。
2. 工具调用的作用是什么？  
   **答**：让模型能够请求执行外部函数，从而完成查询、操作等真实任务。
3. 为什么不能无限依赖长上下文？  
   **答**：上下文窗口有限，且过长会带来成本、延迟与噪声。
