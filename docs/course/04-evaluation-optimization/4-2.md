# Prompt 调优

## 本章目标

学完本章后，你应当能够：

- 说明一份良好 Prompt 的要素。
- 使用示例与输出格式约束模型。
- 建立迭代评估的调优方法。

## 核心概念

- **指令结构**：任务/角色、上下文约束、示例与输出格式的组织方式。
- **少样本示例**：在提示词中给出少量示例引导模型输出。

## 原理与机制

良好的 Prompt 通常包含：角色/任务说明、必要的上下文、少量示例与明确的输出格式。调优时每次只改一个变量，用同一测试集评估变化。

```mermaid
flowchart LR
  A[角色与任务] --> B[上下文约束]
  B --> C[示例]
  C --> D[输出格式]
  D --> E[生成结果]
```

## 企业场景

客服话术需要统一语气和结构。通过给模型设定客服角色、提供两条标准话术示例、并要求 JSON 格式输出，就能显著提升一致性。

## 风险与常见误区

- **误区**：Prompt 越长越好。
- **误区**：一次改动太多，无法归因。
- **风险**：示例带有偏见导致输出偏差。

## 验收标准

能够写出一份结构完整的 Prompt，并说明如何通过单变量迭代进行评估。

## 本章小结

Prompt 调优是低成本高杠杆的优化手段，关键在结构清晰、示例恰当与迭代评估。

## 自测题

1. 一份良好 Prompt 包含哪些要素？  
   **答**：角色/任务、上下文约束、示例与输出格式。
2. 为什么一次只改一个变量？  
   **答**：便于归因，判断是哪项改动带来效果变化。
3. 少样本示例的作用是什么？  
   **答**：用少量示例引导模型输出的风格与结构。
